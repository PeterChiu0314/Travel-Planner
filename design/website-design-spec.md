## 2. 設計目標

### 網站目的

本網站用於：

- 提供多人共同建立、編輯及管理旅遊行程的空間。
- 將每日行程、時間安排、交通資訊與地圖位置整合於同一個工作區。
- 降低使用者在地圖、筆記、試算表與通訊軟體之間切換的需求。
- 讓使用者在旅程規劃階段與實際旅行途中，快速查看需要的資訊。
- 支援單人規劃、多人協作及對外展示行程。

### 核心使用者

- 自由行旅客。
- 共同規劃旅行的朋友、伴侶或家庭。

### 主要需求

- 建立與管理多日旅程。
- 安排景點、住宿與交通。
- 透過時間軸理解每日行程。
- 在地圖中查看地點位置及順序。
- 與其他成員即時共同編輯。
- 分配行李與分攤費用。
- 在手機上查看當日行程與導航資訊。

### 使用情境

- 出發前於桌面版進行完整行程規劃。
- 與旅伴同步討論並調整景點順序、住宿與預算。
- 旅行途中使用手機查看下一個地點。
- 點擊交通卡或地點，啟動 Google Maps 導航。
- 透過公開或展示連結分享行程。

### 核心任務

使用者應能夠：

1. 建立旅程、邀請成員並共同管理多日行程。
2. 在 Timeline 中新增、編輯、排序及查看景點、住宿與交通資訊。
3. 在 Map 中查看地點順序、調整自訂路線並啟動導航。
4. 規劃預算並將花費連結至行程。
5. 清楚辨認目前編輯的旅程、日期及行程狀態。
6. 在不同裝置尺寸下完成主要操作。

## 3. 品牌與設計原則

### 設計關鍵字

簡單、溫暖、自然、輕盈、現代、可信賴、有秩序；具有旅行感，但不過度使用傳統旅遊符號，並帶有日系編輯感與生活感。

### 設計原則

- 優先呈現使用者當下最需要的旅程資訊。
- 每個操作區域只保留清楚的主要行動，避免過多高強度按鈕。
- 讓使用者知道目前所在的旅程、日期與操作模式。
- 新增、刪除、儲存、拖曳與同步操作都必須有明確回饋。
- 維持資訊密度與可讀性的平衡，不以裝飾犧牲操作效率。
- 不只依靠顏色表示狀態，需搭配文字、圖示、外框或位置差異。
- Desktop 以規劃效率為優先；Mobile 以查看與快速操作為優先。
- Timeline 與 Map 必須互相對應，不得形成兩套不一致的資訊。
- 多人協作時避免畫面跳動或覆蓋使用者正在進行的操作。
- Demo 與正式站維持相同的主要視覺與操作邏輯。
- 高風險操作必須提供確認、限制或復原機制。
- 液態玻璃、模糊與透明效果不得降低文字可讀性。

## 4. 網站架構

### 主要頁面與功能

- 登入／驗證頁
- Demo 展示入口
- 旅程列表
- 新增旅程
- 旅程工作區
- Timeline 行程頁
- Map 地圖區
- Day Tabs 日期切換
- 旅程資訊 Header
- 成員管理與邀請
- 帳號區

### 後續規劃

- Budget 預算管理
- Luggage 行李清單
- Share 分享
- Mobile 旅行模式

本產品不採一般企業官網式的「關於我們、文章、服務介紹」作為核心架構，主要導覽以應用程式功能為主。

### 導覽規則

- 主導覽建議最多包含 5 至 7 個主要項目。
- 目前頁面或功能必須有清楚的選取狀態。
- Desktop 以 Sidebar 作為主要導覽方式。
- Sidebar 包含核心功能、旅程列表、新增旅程、帳號資訊與登出操作。
- Header 顯示當前旅程、成員、邀請及頁面相關操作。
- Mobile 不直接縮小 Desktop Sidebar，改用底部導覽列、抽屜式選單或兩者組合。
- Icon 必須搭配 Tooltip、文字或可辨識的選取狀態。
- 旅程列表過長時，在可用高度內滾動。
- 帳號及登出區固定於 Sidebar 下方。

## 5. 頁面規範

### 5.1 Timeline 旅程工作區

#### 頁面目的

- 以每日時間軸規劃及查看行程。
- 整合景點、住宿、交通、時間與地圖位置。
- 支援多人即時共同編輯。
- 讓使用者理解行程卡片的順序與關係。

#### 必要區塊

- 旅程 Header
- Sidebar
- Day Tabs
- Timeline 行程區
- Map 地圖區
- 新增／編輯行程卡片的操作介面
- 成員、邀請及協作狀態
- Loading、Empty、Error、Sync 狀態

#### 主要行動

- 主要 CTA：新增行程／新增目的地。
- 次要 CTA：編輯行程、調整順序、編輯地圖路線、邀請成員、查看導航、新增備案、鎖定或解鎖行程。

#### 狀態

- Loading：保留頁面結構，使用骨架畫面或區塊 Loading，避免版面大幅跳動。
- Empty：顯示清楚說明及「新增第一個行程」行動。
- Error：說明問題與下一步；儲存失敗不得靜默失敗；樂觀更新失敗時回滾。
- Sync：同步失效時嘗試恢復，避免大量干擾性通知。
- Success：新增、儲存、刪除或邀請成功時提供適度回饋。

### 5.2 Map 地圖工作區

#### 頁面目的

- 顯示當日地點及順序。
- 建立 Timeline 與 Map 的雙向對應。
- 搜尋地點、加入行程及調整自訂路線。
- 提供外部 Google Maps 導航入口。

#### 必要區塊

- Google Map
- 地點搜尋框
- 行程 Marker
- 行程路線 Polyline
- 地圖路線編輯模式
- 自訂途經節點
- 缺少座標提示
- 地圖模式退出及狀態提示

#### 路線編輯模式

- 地圖外區域降低視覺強度。
- 暫停可能干擾編輯的 POI 點擊、Marker focus 與自動縮放。
- 點擊地圖外區域可退出編輯模式。
- 節點拖曳期間即時更新折線。
- 節點點擊刪除時需避免誤觸。
- 預設節點數量上限為 5 個；調整時需同步更新 UI 說明與資料限制。

### 6.1 設計方向

目前採用「Warm Taupe Editorial」方向：以 `#68594A` 暖灰棕作為主要品牌色，搭配暖白、米灰、低飽和銅棕與自然綠色狀態，呈現溫暖、穩定、具有生活感的旅程規劃工具。

原始 v0.1 草案曾以灰墨綠 `#445A50` 探索；目前可實作的版本以 [travel-studio-design-system-68594a.json](./travel-studio-design-system-68594a.json) 為準。

- Sidebar 不使用整片深色背景，避免視覺重量過重。
- 狀態色必須搭配文字、圖示或標籤，不可單靠顏色判讀。
- Marker 顏色與 Timeline 順序保持一致。
- 路線色必須與地圖底色具有足夠對比。

```css
font-family:
  Inter,

  "Noto Sans JP",

  sans-serif;
```

| Token | 預設值 | 用途 |
|---|---:|---|
| `font-display` | 36px | 展示型標題 |
| `font-h1` | 28px | 頁面標題 |

### 6.4 間距

基礎間距單位為 `4px`，可透過設計預覽調整：

```text
space-1: 4px
space-2: 8px
space-3: 12px
space-4: 16px
space-6: 24px
space-8: 32px
space-12: 48px
space-16: 64px
```

- 元件內部間距優先使用 8、12、16px。
- 卡片之間優先使用 12 或 16px。
- 區塊之間優先使用 24 或 32px。
- 不任意加入間距系統以外的數值；特殊情況需註記原因。

### 6.5 圓角、陰影與透明效果

| Token | 預設值 | 用途 |
|---|---:|---|
| `radius-sm` | 8px | 小元件、按鈕、輸入欄位 |
| `radius-md` | 12px | 行程卡、一般 Panel |
| `radius-lg` | 16px | 大型 Panel、主要容器 |
| `radius-xl` | 20px | Modal、大型浮層 |
| Pill | 999px | Badge、狀態標籤 |

- 卡片以 Border 優先，陰影保持極淡。
- Dropdown、Modal 與浮動工具列可使用較明顯陰影。
- Hover 時只略微提高陰影或邊界對比。
- 避免高濃度純黑陰影。
- 液態玻璃需搭配半透明暖白、適度模糊、細緻邊框與低強度陰影。
- 透明效果不得造成文字、按鈕或底圖難以辨識。

## 7. 元件規範

每個元件都必須定義：使用時機、尺寸、文字規則、Default、Hover、Focus、Active、Disabled、Loading、Error、Responsive 行為、鍵盤操作與是否具有破壞性。

### 7.1 Button

- Primary：用於頁面或區塊最主要的行動；同一視覺區域原則上只保留一個。
- Secondary：用於次要行動或替代選項，視覺重量低於 Primary。
- Ghost：用於收合、更多選項、取消等低強度操作。
- Danger：用於刪除、移除成員或不可逆操作；執行前依風險提供確認。
- Disabled：不得只依靠透明度表示；應移除 Hover、Pointer 與鍵盤觸發能力，必要時說明原因。
- Icon Button：最小操作區域建議 40×40px；必須提供 `aria-label` 與 Tooltip 或鄰近文字。

按鈕文字應以動詞開頭，例如「新增行程」、「儲存變更」、「邀請成員」、「開始導航」。避免使用缺乏情境的「確定」、「送出」或「執行」。

### 7.2 Input／Select

- 所有欄位皆需有 Label；Placeholder 不得取代 Label。
- Focus 使用清楚外框，不得只改變細微背景色。
- Error 必須包含錯誤外框與可理解的錯誤訊息。
- 搜尋結果支援方向鍵與 Enter 選取。
- 自動完成欄位需支援中文輸入法組字狀態。
- Select、Dropdown 需具備鍵盤操作、選取、Hover、Focus 與長清單滾動狀態。

### 7.3 Panel／Card

- 景點卡、住宿卡與交通卡維持一致的基礎尺寸與層級邏輯。
- 主要資訊優先顯示名稱、時間、類型與必要狀態。
- 次要資訊可於展開後查看。
- 可拖曳卡片要有明確拖曳範圍或 Handle。
- 選取行程卡時，對應 Marker 必須同步強調。
- 固定卡片不可拖曳、刪除或進行主備互換，並保留解鎖入口。

### 7.4 Modal／Dialog

- 用於邀請成員、編輯角色、高風險確認與複雜表單。
- 開啟後 Focus 進入 Dialog，關閉後回到原觸發元件。
- 支援 Escape 關閉；高風險流程可視情況限制。
- 不同時堆疊多個 Modal。
- 行動按鈕位置保持一致。

### 7.5 Toast／通知

- 用於簡短、非阻斷式的操作回饋。
- 成功通知停留時間較短；錯誤通知停留較久並提供下一步。
- 自動儲存不應持續產生 Toast。
- 多人同步狀態優先使用區域狀態文字，不大量使用 Toast。

### 7.6 警示與狀態

- Warning 用於待確認、即將影響行程或需要注意的狀態。
- Error 用於操作失敗、資料無法儲存或破壞性操作。
- Success 用於已儲存、已同步或完成的狀態。
- Info 用於一般提示、載入或補充資訊。
- 每種狀態都需搭配語意文字，不得只顯示色塊。

## 8. 響應式規範

### Desktop

- 主要用途：完整行程規劃與多人協作。
- 建議最低支援寬度：1280px。
- 主要欄位：Sidebar、Timeline、Map。
- Timeline 與 Map 應可同時查看。
- 視窗縮小時先縮減次要留白與 Map 寬度，不直接壓縮文字。

### Tablet

- 主要用途：中度編輯及行程查看。
- Sidebar 可收合為窄版 Icon Rail 或抽屜式選單。
- Timeline 保持單欄。
- Map 可與 Timeline 上下排列，或使用可切換面板。
- Header 簡化低優先操作。

### Mobile

- 主要用途：旅途中查看、快速編輯與導航。
- 使用單欄，不直接縮小 Desktop 版。
- Timeline 與 Map 使用頁籤、分段控制或可切換模式。
- 主要保留今日行程、下一個地點、時間、交通、導航與簡易備註。
- 低頻管理功能收進更多選單。
- Hover 不得作為唯一互動提示。

暫定斷點：

- Mobile：小於 768px
- Tablet：768–1199px
- Desktop：1200px 以上
- Large Desktop：1440px 以上

實際斷點應依版面失效位置調整，而非只依常見裝置尺寸決定。

## 9. 無障礙規範

- 一般文字與背景至少符合 WCAG AA。
- 一般文字對比度至少 4.5:1；大型文字至少 3:1。
- 所有互動元件可使用鍵盤操作。
- Focus 狀態不可移除，且在深色、淺色與地圖背景上清楚可見。
- 圖片提供替代文字；裝飾性圖片使用空白替代文字。
- 表單欄位具有清楚 Label 與錯誤說明。
- 不只依靠顏色表示成功、錯誤、分類或選取。
- Icon Button 提供可讀名稱。
- Modal 正確管理 Focus。
- Tooltip 不包含完成操作所必須的唯一資訊。
- 拖曳功能提供替代排序方式。
- 尊重 `prefers-reduced-motion`。
- 地圖不是唯一資訊來源，所有地點與順序也能由 Timeline 讀取。
- 重要點擊與觸控目標建議至少 44×44px。

## 10. 內容規範

### 標題與語氣

- 簡潔、自然、直接，以使用者任務為中心。
- 避免過度商業化、浮誇或口號式語氣。
- 優先使用繁體中文。
- 旅程名稱可具有個性，但系統標題保持清楚。

### 錯誤訊息

錯誤訊息包含：發生什麼事、哪個操作未完成、使用者下一步可以怎麼做。

範例：

- 無法儲存行程，請檢查網路連線後再試一次。
- 地圖載入失敗，請重新整理頁面。
- 此行程目前由其他成員編輯，請稍後再試。
- 無法取得地點資訊，你仍可手動輸入名稱與位置。

避免直接顯示：`Error 500`、`Database error`、`API request failed`、`Something went wrong`。

### 日期與數字

- 完整日期：2026 年 7 月 13 日
- 短日期：2026/07/13
- 行程日期：7/13（一）
- 時間：24 小時制，例如 09:30
- 日期範圍：2026/07/13–2026/07/18
- 一般數字使用千分位，例如 12,500。
- 距離小於 1 公里使用公尺；1 公里以上使用公里。
- 時間長度使用「15 分鐘」、「1 小時 30 分鐘」。
- 貨幣依旅程設定；尚未設定時可使用新臺幣 NT$1,200。

### 用詞一致性

- 「導航」：開啟外部地圖導航。
- 「編輯地圖路線」：網站內調整路線節點。
- 「交通時間」：使用者手動輸入的規劃資訊，不暗示即時交通預測。
- 已有清楚中文對應時，介面以中文為主。

## 11. 驗收標準

### 基本功能

- 可建立及切換旅程。
- 可新增、編輯及刪除行程。
- 可切換日期並查看正確資料。
- Timeline 與 Map 顯示順序一致。
- 點擊卡片可聚焦 Marker；點擊 Marker 可定位卡片。
- 地點搜尋、選取及加入行程流程正常。
- 導航按鈕產生正確的 Google Maps 導航連結。
- 路線節點可新增、拖曳及刪除。
- 多人協作最終狀態正確收斂。
- 儲存失敗可回滾，不留下錯誤的本地狀態。

### 視覺與元件

- 所有頁面符合版面、色彩與元件規範。
- 相同功能不得在不同頁面使用互相衝突的樣式。
- 主要 CTA 容易辨識。
- Hover、Focus、Active、Disabled、Loading 及 Error 狀態皆有設計。
- Marker 樣式一致，數字與 Timeline 順序相符。
- Sidebar、Header、Timeline 與 Map 的視覺層級清楚。
- 透明與玻璃效果不影響可讀性。

### 響應式與無障礙

- 手機、平板及桌面版均可正常使用。
- 不出現不必要的水平捲動。
- 文字不被截斷至無法理解。
- 主要操作不被固定元件遮擋。
- 觸控操作不依賴 Hover。
- 通過基本鍵盤操作檢查。
- Focus 順序合理且可見。
- 表單具有 Label 與錯誤說明。
- 文字及主要元件符合最低對比度。
- 地圖資訊可由非地圖介面取得。

### 技術與品質

- Production build 通過。
- 核心自動化測試通過。
- Demo 與正式站主要 UI、元件及互動邏輯保持一致。
- Demo 不讀寫正式 Supabase、Realtime 或正式資料。
- 正式站資料存取符合權限與 RLS 規則。
- Browser Console 不得出現未處理錯誤。
- 主要流程完成 Chrome 實機或自動化 QA。
- 變更不得破壞既有 Timeline、Map、協作及排序功能。
