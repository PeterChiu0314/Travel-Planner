## #12 — End editing before switching sidebar tabs

`changePanel()` now waits for `close()` before changing to Detail/Stats. A genuinely clean form exits directly, including edits reverted to their original values. A dirty form uses the existing site dialog with **繼續編輯 / 放棄修改**. Continue retains the form and lease; confirmed discard removes the matching draft only after cleanup is confirmed. A restored unsaved draft stays dirty even after admission if saving fails.

The lease client no longer deletes its local capability before the DB acknowledges release. Releasing/uncertain capabilities cannot save, renew or be reused for another editor. Refused, offline and unanswered releases remain retryable; the UI stays in the editor and reports the incomplete release. A ten-second client acknowledgement timeout bounds waiting; the existing seven-minute server expiry and 60-second renewal schedule are unchanged. A stalled renewal does not block release, and its late response cannot restore local authority. Detached cleanup remains tracked while in flight and retryable after failure. Context/generation checks prevent a late exit from redirecting another account/trip.

The losing editor tracks its blocked resource. After successful collaboration reconciliation, it rechecks the authenticated metadata RPC before clearing only that obsolete lock warning. Failed/unverified metadata cannot clear it. It never acquires a lease or opens a form automatically. This adds no financial reload and no new polling interval.

## #11 — Successful save/cancel returns to Detail

Successful save chooses the returned canonical record ID and opens Detail. Cancel retains the edited existing ID and returns to its unchanged Detail. A new save without an ID clears selection and shows the existing Detail empty state. Remote deletion clears orphan selection. The intermediate **繼續編輯此項目** button is removed; explicit Edit entry still works.

Validation failures, optimistic conflicts, lease loss and failed release stay in the form. If the write committed but refresh/release failed, the UI explicitly reports the committed write and incomplete cleanup/sync; it does not display stale Detail as a successful fresh result or automatically repeat the financial mutation. Confirmed committed input is clean, while uncommitted restored input remains protected.

## #14 — One primary selection per user; all real locks remain visible

Priority is computed across all metadata, including own-session entries, **before** filtering the local session from remote frames:

1. Any live edit lease suppresses that user's selection hints. Every distinct real edit lease remains visible.
2. With no edit, select only the latest real action using server `selected_at`.
3. Deduplicate same-user/same-resource hints; preserve different users' colors and the existing local selection.

The old RPC exposes expiry but no trustworthy activity order; heartbeats rewrite expiry. Receiver arrival order cannot recover initial/hidden-tab history reliably. UI-only expiry sorting was therefore rejected.
