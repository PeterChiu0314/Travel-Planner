# Issue 29 旅程邀請連結驗收

Staging 已套用 `20261126120241_issue29_trip_invite_lifecycle.sql`。升級前 3 筆邀請皆已撤銷，原始記錄保留。遷移演練比對所有成員列，核准和待審狀態均相同。真實 PostgreSQL 的兩條連線同時建立，再持同一舊 Token 重建，兩次操作分別得到相同結果；最後只有一筆未撤銷。一次性測試旅程、帳號與邀請清理後皆為 0 筆。

## 手動驗收

使用本分支前端連到 Staging。準備可管理的測試旅程與另一個測試帳號。

1. 擁有者開啟「成員與邀請」，首次應顯示「建立邀請連結」。關閉再開啟，仍須手動按建立。
2. 建立後記下有效期限，複製網址。關閉重開、重新整理、用另一個瀏覽器登入同一擁有者帳號，三次都應看到同一網址與期限。
3. 在兩個瀏覽器都顯示同一舊連結時，同時按「重新產生邀請連結」。重新開啟兩端視窗，均應顯示同一新網址。
4. 另一帳號使用舊網址登入應看到無效提示。使用新網址應可送出待審申請。再次重建邀請後，原待審申請仍可由擁有者核准。
5. 編輯者與檢視者均不可讀取或產生邀請。抵達到期時間後，原址拒絕新申請；擁有者可在視窗建立新連結。自動化 SQL 在測試交易內模擬精確到期邊界，執行後回滾。
