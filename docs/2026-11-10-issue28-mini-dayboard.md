# Issue #28 關聯行程 Mini Dayboard

側欄列出已關聯的行程。新增或編輯會開啟 Mini Dayboard，依容器寬度同時顯示一至四個 Day，所有日期可連續橫向瀏覽。沿用 Timeline 的景點排序及交通卡配對。資料若在不同 Day 顯示同一行程 ID，選取會同步。

選取沿用 `links` 群組的 debounce、版本驗證及回執復原。關閉時等待進行中的請求，再送出最後一筆已變更的選取，確認後釋放租約。新支出先完成命名並建立記錄，才能取得關聯租約。

## Staging 手測

1. 用有編輯權限的帳號打開預算項目，從側欄開啟關聯行程。從卡片上按住滑鼠橫向拖拉，到最後一天再返回。確認拖拉後卡片維持原本選取狀態，水平捲軸隱藏，滾輪仍可垂直捲動。用觸控板、觸控滑動與鍵盤方向鍵檢查同一區域。
2. 快速點選不同 Day 的卡片，切換搜尋和分類，再清除篩選，確認已選卡片仍帶勾。點選後立即按 X 或 Esc，確認側欄摘要更新。重新開啟核對已選，並從側欄快速移除一筆。
3. 用第二個帳號開啟同一支出。第一個帳號編輯關聯時，第二個帳號能讀摘要、編輯備註或操作其他支出的關聯。同一支出的關聯入口應顯示對方協作色並停用。
4. 開啟時確認頁尾顯示「準備中…」，卡片在取得租約後可選。乾淨閒置約 20 秒後，頁尾顯示「編輯已暫停」。點一張卡片，確認這次選取在重新驗證後生效。再次閒置後讓第二個帳號接手，確認第一個帳號的視窗自動關閉，側欄入口顯示對方協作色。過程不會出現手動取得編輯權的按鈕。
5. 有編輯權時切出再切回，確認同一視窗自動嘗試一次取得新租約。若另一個帳號已接手，已存妥的視窗會關閉。斷線或回執待確認時，核對頁尾狀態和已選卡片，視窗會保留草稿，待結果釐清後再處理。

GitHub Actions 執行 [多日操作與雙帳號情境](../tests/expenseLinks.spec.js) 及 [閒置和回執邊界](../tests/expenseLinks.test.mjs)。Chromium 的雙帳號情境使用隔離 SQL 和 Realtime 事件替身。Staging 的實際帳號與裝置需依上列步驟手測。
